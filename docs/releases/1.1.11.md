# gTunes 1.1.11

gTunes 1.1.11 is The One Queue Release. The sidebar "Next Up" card stays out of the way on the pages that already show the queue. It also moves settings into the window and stops a weak connection from eating part of a track.

## Highlights

### The queue stays in one place

- The card no longer comes back on the Next Up page in a tall window. The page rule hid it, then the layout tier re-showed it within 200ms, so a full screen showed the queue twice: once in the content area and once in the sidebar.
- Both owners now ask one question. `LayoutClass::shows_sidebar_queue_card(page)` folds the page rule into the tier rule: the card needs a tall window with a real sidebar, and a page that is not Next Up or Radio.
- Nothing else moves. The card is still there on Tracks, Albums, Artists and Playlists, still gone in a short window, and the "Next Up" nav row still stands in for it wherever the card is gone.

### Settings stays inside the window

- The settings menu is no longer a popover. A popover is its own surface, so the compositor drew it outside the app window, and with gTunes against the right edge of the screen the menu spilled past the window and got clipped.
- It is now a panel inside the window: same rows, no speech bubble, a card with the rest of the window dimmed behind it, Escape or a click outside to close, and it slides the app's usual 180ms.
- It cannot leave the window. The panel is clamped inside the bounds when it opens and again whenever the window is resized under it, and on a short window the menu scrolls instead of running off the bottom edge.

### A dropped connection pauses instead of skipping ahead

- When the wifi cut out mid-track, the audio stopped but the playhead kept moving, and when the connection came back the track was ahead of the point where it stopped. The missed section was simply gone.
- Playback now holds while the source is dry. Position cannot advance while the pipeline is paused, so when the network returns the track carries on from exactly where you were.
- The status line says `Buffering | 42%` or `Buffering | waiting for network` while it waits, and the play button shows the loading spinner. A stall that clears in a blink is not flashed at you.
- A stream that stalls without saying so is caught as well: if the position has not moved for two and a half seconds, playback is held the same way until data is flowing again.

### Scrolling the grids is smooth now

- Album and artist grids stopped re-styling the window in the background. The layout watcher re-applied the window's CSS classes on every 200ms tick because it compared them order-sensitively and GTK hands the list back in its own order, so every tick restyled a tree holding a few hundred tiles: five or six dropped frames a second, 58-62ms each, whether or not you were scrolling.
- Opening Albums or Artists again reuses the tiles it already built. It used to clear them and decode 450 album covers on the main thread every visit; a grid now returns early when it would render exactly what it is already showing.
- On a 450-album grid the scroll sweep went from 5-6 frames a second over 20ms with a worst frame of 58-62ms to 0-1 over 20ms with a worst frame of 7-9ms.

## Notes

- The window's layout tier is enforced on every watcher tick and could only see the window, so it undid the decision the page made in `collections.rs`. Both callers now share one predicate instead of each computing their own.
- The regression test for the card covers the pairs: Next Up and Radio hide the card at full screen, the other four pages keep it, and a short window hides it whatever the page.
- The settings panel is an overlay child of a window-level `GtkOverlay` in `src/ui/settings_panel.rs`, so the window clips it. `sync_settings_panel` re-clamps its rect on open and on every layout watcher tick, and it is the reason a resized window cannot leave the menu hanging off the edge.
- The grid work is in two places: `src/ui/layout.rs` compares the window's CSS classes as a set so a tick only restyles when the tier actually changes, and `collections.rs` keeps a per-grid fingerprint of what the tiles show so a refresh with the same content returns without touching them. `src/ui/perf.rs` carries the frame-timing and scroll-sweep hooks (`GTUNES_UI_PERF`, `GTUNES_PERF_SCROLL`, `GTUNES_PERF_CYCLE`), which are inert unless the variables are set.
- The stall fix lives in `src/playback/mod.rs`. A buffering message under 100% pauses the pipeline and 100% resumes it; `poll_stall` covers sources that never report buffering, and `stall_action` is the pure policy behind it. A healthy source flaps between nearly-full and full, so `is_buffering` debounces 400ms before the UI shows anything.
- Two bugs in the same path are fixed with it: an EOS that follows a stream error was being treated as a track end, which swallowed the error and skipped to the next song, and the initial-loading flag was cleared mid-stream so no loading state could ever survive a stall.
