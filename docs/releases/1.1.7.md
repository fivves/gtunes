# gTunes 1.1.7

gTunes 1.1.7 restores sign-in and playback against Jellyfin 12.0.

## Highlights

- Fix signing in to Jellyfin 12.0. That release removed the legacy `X-Emby-Authorization` header gTunes sent to `Users/AuthenticateByName`, so the server answered every attempt with HTTP 400 and a saved session could never be refreshed or replaced.
- Send media stream tokens in the `Authorization` header Jellyfin 12 accepts, instead of the removed `X-Emby-Token` header, so direct and transcoded playback authenticate again.
- Rebuild cached track stream headers from the current session when a cached library is loaded, so a library cached before the upgrade does not keep sending the removed headers.

## Notes

- Add the GStreamer packages playback actually needs to the build instructions. `gst-plugins-good` provides the HTTP source element, so a machine set up from the previous instructions could sign in and browse a library but could not play anything, failing with `No URI handler implemented for "http"`.
- You will need to sign in once after this update. The access token Jellyfin issued before the upgrade is no longer accepted, so the saved session cannot be reused.
- The new headers work with older Jellyfin releases too, so this is safe to keep running if your server is still on 10.x.
