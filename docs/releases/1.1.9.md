# gTunes 1.1.9

gTunes 1.1.9 is The Self-Healing Release. Discord no longer keeps showing a track you already stopped playing until you close the app.

## Highlights

- Clear Discord Rich Presence properly when playback stops. Pausing used to send exactly one clear, and if anything between gTunes and Discord dropped that single message, the track stayed on your profile with its timer still counting, sometimes for days.
- Re-assert the cleared state on the reconcile timer. The worker already knew it should do this, but the code path that runs when the timer fired did nothing, so the retry never happened. The tick now runs the reconcile it was always meant to run.
- Nothing changes while a track is playing. A playing activity is still published once per playback change, so Discord's own elapsed timer is not restarted on every tick.

## Notes

- The reconcile tick is the timeout arm of the worker loop in `src/discord.rs`. The interval is now carried on the worker rather than read from the constant at the call site, which lets a test drive the real loop with a short interval.
- The regression test drives that loop and asserts the clear is sent again after the interval elapses. The existing test calls `reconcile()` directly, which is exactly why an empty tick could pass CI while the bug shipped.
