# gTunes 1.1.10

gTunes 1.1.10 is The Fits Release. The track list no longer grows a horizontal scrollbar at half size, the one that only scrolled a few blank pixels.

## Highlights

- The four track columns fit every window that shows all four. Their widths were pinned at 260 + 160 + 220 + 66 = 706px, and half size gives the table 701px, so the list spent five pixels of every half-size window scrolled sideways: a scrollbar with a near-full-width thumb that moved a hair and revealed blank ends. The floors are now 236 + 136 + 196 + 66 = 634px, which leaves room for a vertical scrollbar as well.
- Nothing else changed visually. `fixed_width` is a column's floor, not its size: `ColumnView` still shares every surplus pixel across the expand columns, so half size lands at 258/158/218/66 and a full screen sits within a pixel or two of the old widths.
- A regression test now pins the column total against the narrowest full-width window, so retuning a width or the width tier cannot quietly bring the scrollbar back.

## Notes

- This class of bug is invisible from the outside: the app never clips and the root's own minimum stays small, because a scrolled window is allowed to be narrower than its child. The only symptom is the scrollbar, which is why `GTUNES_LAYOUT_DEBUG` now logs what the table needs against what it is given, e.g. `track table needs 634px, column view gets 701px, scroller 701px (h-adj 701/701)`, with `<-- H-SCROLLS` when it is short.
- The Full width tier reaches down to 900px, so that is the window the total has to fit (900 - 240 sidebar = 660px), not just half size.
