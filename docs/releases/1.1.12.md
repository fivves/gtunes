# gTunes 1.1.12

gTunes 1.1.12 is The Steady Release. It is everything since 1.1.8 in one drop: a dropped connection holds your place instead of skipping ahead, the window lays itself out at any size instead of clipping, the album grids scroll smoothly, and Discord stops showing a track you already stopped.

## Highlights

### A dropped connection holds your place

- When the wifi cut out mid-track, the audio stopped but the playhead kept moving, and when the connection came back the track was ahead of the point where it stopped. The missed section was simply gone.
- Playback now holds while the source is dry. Position cannot advance while the pipeline is paused, so when the network returns the track carries on from exactly where you were.
- The status line says `Buffering | 42%` or `Buffering | waiting for network` while it waits, and the play button shows the loading spinner. A stall that clears in a blink is not flashed at you.
- A stream that stalls without saying so is caught as well: if the position has not moved for two and a half seconds, playback is held the same way until data is flowing again.

### The window keeps its shape at every size

- The four track columns fit every window that shows all four. Their floors were pinned at 260 + 160 + 220 + 66 = 706px while half size gives the table 701px, so the list spent five pixels of every half-size window scrolled sideways: a scrollbar with a near-full-width thumb that moved a hair and revealed blank ends. The floors are now 236 + 136 + 196 + 66 = 634px, which leaves room for a vertical scrollbar as well.
- Nothing else changed visually. A column's floor is not its size: every surplus pixel is still shared across the expand columns, so half size lands at 258/158/218/66 and a full screen sits within a pixel or two of the old widths.
- The sidebar cover art comes back in a short window that has room for it. A window under 1000px tall used to drop the 220px square because the tier reflowed the whole sidebar for height, so a 763px-tall window with 140px of empty sidebar under the nav list still showed a blank corner. The tier is only the default now, and the art is shown wherever the sidebar's stack can actually hold it.
- The tiny tiles still drop the art, and the icon rail never shows it at any height.
- The search field stays in the player bar at every size. Coming back to a wide window used to return the search box to the bar without the field ever rendering, and the compact menu button that had hidden it was gone too, so the search was unreachable at full size.

### The queue has one place, whatever the size

- The "Next Up" card no longer comes back on the Next Up page in a tall window. The page rule hid it, then the layout tier re-showed it within 200ms, so a full screen showed the queue twice: once in the content area and once in the sidebar.
- Both owners now ask one question. The card needs a tall window with a real sidebar, and a page that is not Next Up or Radio.
- Nothing else moves. The card is still there on Tracks, Albums, Artists and Playlists, still gone in a short window, and the "Next Up" nav row still stands in for it wherever the card is gone.

### Settings stays inside the window

- The settings menu is no longer a popover. A popover is its own surface, so the compositor drew it outside the app window, and with gTunes against the right edge of the screen the menu spilled past the window and got clipped.
- It is now a panel inside the window: same rows, no speech bubble, a card with the rest of the window dimmed behind it, Escape or a click outside to close, and it slides the app's usual 180ms.
- It cannot leave the window. The panel is clamped inside the bounds when it opens and again whenever the window is resized under it, and on a short window the menu scrolls instead of running off the bottom edge.

### Scrolling the grids is smooth now

- Album and artist grids stopped re-styling the window in the background. The layout watcher re-applied the window's CSS classes on every 200ms tick because it compared them order-sensitively and GTK hands the list back in its own order, so every tick restyled a tree holding a few hundred tiles: five or six dropped frames a second, 58-62ms each, whether or not you were scrolling.
- Opening Albums or Artists again reuses the tiles it already built. It used to clear them and decode 450 album covers on the main thread every visit; a grid now returns early when it would render exactly what it is already showing.
- On a 450-album grid the scroll sweep went from 5-6 frames a second over 20ms with a worst frame of 58-62ms to 0-1 over 20ms with a worst frame of 7-9ms.

### Discord clears when you stop

- Discord Rich Presence clears properly when playback stops. Pausing used to send exactly one clear, and if anything between gTunes and Discord dropped that single message, the track stayed on your profile with its timer still counting, sometimes for days.
- The cleared state is re-asserted on the reconcile timer. The worker already knew it should do this, but the code path that ran when the timer fired did nothing, so the retry never happened.
- Nothing changes while a track is playing. A playing activity is still published once per playback change, so Discord's own elapsed timer is not restarted on every tick.

## Notes

- The stall fix lives in `src/playback/mod.rs`. A buffering message under 100% pauses the pipeline and 100% resumes it; `poll_stall` covers sources that never report buffering, and `stall_action` is the pure policy behind it. A healthy source flaps between nearly-full and full, so `is_buffering` debounces 400ms before the UI shows anything. Two bugs in the same path are fixed with it: an EOS that follows a stream error was being treated as a track end, which swallowed the error and skipped to the next song, and the initial-loading flag was cleared mid-stream so no loading state could ever survive a stall.
- The column total is pinned by a test against the narrowest full-width window, so retuning a width or the width tier cannot quietly bring the horizontal scrollbar back. This class of bug is invisible from the outside, because a scrolled window is allowed to be narrower than its child and the app never clips, so `GTUNES_LAYOUT_DEBUG` now logs `track table needs ... , column view gets ...` with `<-- H-SCROLLS` when it is short.
- The art's fit test is two numbers in `src/ui/layout.rs`: the sidebar's measured minimum without the art, plus `COVER_ART_STACK_HEIGHT` (the 220px square, its 12px margin and the sidebar's 4px spacing), against the height of the body box the sidebar sits in. It is compared to the body and not to the sidebar because the sidebar is allocated at least its own minimum, so it would report the inflated number and the test would always agree with itself. `GTUNES_LAYOUT_DEBUG=1` prints `cover art needs Npx, body has Mpx -> shown|hidden`, which is how the 702px boundary was measured.
- The window's layout tier is enforced on every watcher tick and could only see the window, so it undid the decision the page made in `collections.rs`. Both callers now share one predicate instead of each computing their own, and the regression test covers the pairs: Next Up and Radio hide the card at full screen, the other four pages keep it, and a short window hides it whatever the page.
- The settings panel is an overlay child of a window-level `GtkOverlay` in `src/ui/settings_panel.rs`, so the window clips it. `sync_settings_panel` re-clamps its rect on open and on every layout watcher tick, and it is the reason a resized window cannot leave the menu hanging off the edge.
- The grid work is in two places: `src/ui/layout.rs` compares the window's CSS classes as a set so a tick only restyles when the tier actually changes, and `collections.rs` keeps a per-grid fingerprint of what the tiles show so a refresh with the same content returns without touching them. `src/ui/perf.rs` carries the frame-timing and scroll-sweep hooks (`GTUNES_UI_PERF`, `GTUNES_PERF_SCROLL`, `GTUNES_PERF_CYCLE`), which are inert unless the variables are set.
- The search field is built inside the player bar and stays there. The earlier design moved the real widgets into the compact menu's popover, which is only reachable while the button that opens it is visible; the button is now never shown, because its popover would be empty.
- The Discord reconcile tick is the timeout arm of the worker loop in `src/discord.rs`. The interval is carried on the worker rather than read from the constant at the call site, and the regression test drives the real loop and asserts the clear is sent again after the interval elapses. A test that calls `reconcile()` directly is exactly why an empty tick could pass CI while the bug shipped.
